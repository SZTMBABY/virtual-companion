## 二、技术选型与实测证据

### 2.1 Live2D 渲染 — WebView 路线（已验证跑通）

| 项 | 实测值 | 结论 |
|---|---|---|
| WebView | 103.0.5060.71（Chromium 103, 2022），唯一提供者 | 可用，但无 GMS |
| Cubism Core | `csmGetVersion=83951616` = 0x050100C0 → **5.1.0**；`csmGetLatestMocVersion=5` | 能解析 moc3 v5 |
| WebGL | `webgl2=YES`，PowerVR GE8300，`MAX_TEXTURE=4096`，`MAX_VIEWPORT=4096` | **8192 原贴图传不上去** |
| 解析结果 | `Moc.fromArrayBuffer=OK`、`paramCount=174`、`drawableCount=136`、`partCount=35` | 模型结构完整 |
| 渲染帧率 | 横屏 640×480 → **fps 22.0**；竖屏 480×640 → **fps 21.5** | 够用（角色是静态姿态 + 参数动画） |
| 内存 | `dumpsys meminfo` TOTAL PSS **113MB**（.apk mmap 56.7MB + Java 9.3MB + Native 9MB） | 3GB 机有余量 |
| 参数索引 | `ParamEyeLOpen`=14、`ParamMouthOpenY`=18、`ParamAngleX`=27、`ParamBreath`=37 | 点号访问有效 |

**踩过的坑（都已在代码里修好）**：
- `file:///android_asset/` 的 XHR 要开 `allowFileAccess` + `allowFileAccessFromFileURLs` + `allowUniversalAccessFromFileURLs`（三个都要，`@Suppress("DEPRECATION")`）。不需要 `WebViewAssetLoader`。
- 画布尺寸不能用 `window.innerWidth`（初版取到 0 → canvas 0×0 → 全黑），要 `window.innerWidth || document.documentElement.clientWidth || 640`。
- 缩放要用 `model.getBounds()`，不能用 `model.width/height`（后者含未裁切留白）；`s = min(CW/b.width, CH/b.height) * 0.92`。
- 模型自带的 `model3.json` 里 `EyeBlink.Ids` 和 `LipSync.Ids` 都是**空数组**，必须自己补 `["ParamEyeLOpen","ParamEyeROpen"]` / `["ParamMouthOpenY"]`，否则不眨眼不口型。
- 贴图 8192×8192 → 降到 2048×2048（1.1MB PNG / 16MiB 显存）。内容 bbox 只占画布 49.64%，降采样无肉眼损失。
- 包内 **0 个 motion3**、**0 个 pose3**；只有 15 个 exp3 和 physics3。所以「动作」全部靠 cdi3 的 174 个参数代码驱动 + physics 被动摆动。

### 2.2 语音链路

**麦克风（实测全部通过）**
- `AudioRecord` 16kHz 单声道 `state=3`，3.9 秒采 46400 样本、峰值 20289、几乎全非零 → `MIC_OK`。
- **AEC 可用**（`Acoustic Echo Canceler / AOSP`，UUID `bb392ec0-8d4d-11e0-a896-0002a5d5c51b`）；NS / AGC 不可用 → 需要在软件侧做简易降噪 + 增益。
- **无任何 TTS 引擎**（`tts_default_synth=null`），所以必须自带播放器，`AudioTrack` 直写 PCM。

**唤醒词 KWS（sherpa-onnx，已落盘）**
- AAR：`app/libs/sherpa-onnx.aar` 49.4MB，打包 `abiFilters += "arm64-v8a"` 后仅含一个 ABI。
- 模型：`sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20`，chunk-16 int8 三件套 = 8.4MB。
- 唤醒词拼写已逐 token 用 `tokens.txt` 的 `grep -qx` 校验：`x iǎo j īng @小鲸` 全部命中。
- API 已用 `javap` 核实签名（`KeywordSpotter(AssetManager, KeywordSpotterConfig)`、`createStream(String)`、`decode`、`isReady`、`getResult(): KeywordSpotterResult`）。

**ASR 双引擎**
- 云端（默认）：腾讯 `wss://asr.cloud.tencent.com/asr/v2/<appid>`，**HMAC-SHA1 简单签名**（不是 TC3），16k，200ms / 6400 字节一包，1 元/小时。
- 本地（可切）：`sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23` int8 三件套 = 25MB，已在 `assets/asr/`。A53 上 RTF 估 0.5–0.7（推测，待真机实测）。
- 降级策略：云端连续失败 2 次自动切本地并提示，不打断对话。

**TTS（火山豆包 2.0，已核实文档）**
- `wss://openspeech.bytedance.com/api/v3/tts/bidirection`
- Header：`X-Api-App-Id`、`X-Api-Access-Key`、`X-Api-Resource-Id: seed-tts-2.0`、`X-Api-Connect-Id`(UUID)
- 二进制帧：`byte0=0x11`(version1|headerSize1) · `byte1=type<<4|flags` · `byte2=serial<<4|compress` · `byte3=0` · `4B 大端 payload 长度` · `payload`
- 请求 PCM：`audio_config { channel:1, format:"pcm_s16le", sample_rate:24000 }`
- 音色：`saturn_zh_female_keainvsheng_tob`（可爱女生，默认）/ `nuanxinxuejie` / `tiexinnvyou` / `bingjiaojiejie` / `wenrouwenya`
- 流式输出 → `AudioTrack` 边收边写，首字延迟约 300–500ms；同一时刻只有一个播放器（借鉴 Servant 的「网关原子领取播放权」，防叠音）。

### 2.3 记忆（billion-context Phase 1 移植）

billion-context 的内核契约是「**core 从不让模型调用**，摘要由外部 LLM 写好当字符串传进来，core 无状态无 I/O」。所以切到手机上天然成立：摘要交给云端 API，本地只跑纯 CPU 编排。

移植范围（Phase 1，约 1,800 行 Kotlin）：

| 机制 | 原实现 | 手机端改法 |
|---|---|---|
| `mNNNNN` 稳定号 | 内核 `render-refs` 注入 | 消息入库时自增号，存 SQLite |
| T1/T2/T3 分层 block | tier2 目标 50–150 tok、tier3 30–60 tok | 保留，tier 阈值调小（伴侣对话体量小） |
| 模型自写摘要 + nudge | token 增长 22.5K 或窗口 75% 触发 | 改成「每 20 轮」或「上下文 > 12K token」（50K 闸门对伴侣 App 永不触发） |
| 分层检索 | hybrid = BM25(k1=1.2,b=0.75) + fuzzy + substring，CJK bigram | **FTS4 `tokenize=icu zh_CN`** + 纯 Kotlin BM25（实测 FTS4 中文有效：`中华`/`人民`/`国歌` 命中，10 万行 match 0.05s） |
| decompress 回放 | 预存 one-view/full-view | 原文永不删，只从 wire 移除；回放按 ref 取 |
| `acp_rule` | maxRules=50 / 300 字符 | 保留 —— 「用户明确纠正过一次的事永久记住」 |
| 语义检索 | 默认**根本没注册**（`semantic` 仅可选） | 不做。默认 hybrid 就是词法，零模型召回够用 |

**关键约束**：`sqlite3` 是 **3.28.0**，**FTS5 不可用**（`no such module: fts5`），只有 FTS4/FTS3。所以不能指望 `bm25()`，BM25 自己算。

**`docs/research/memory-candidates.md`（557 行，全部在目标机实测）推翻了三个我原本的判断**：

| 原判断 | 实测结论 |
|---|---|
| FTS4 `tokenize=icu zh_CN` 中文够用 | **不够**。默认 `unicode61` / `simple` 存中文检索能力为零（`MATCH '妹妹'` 返回 0 行）；`icu zh_CN` 比默认好（`MATCH '火锅'` 命中 1 行 vs 0 行）但仍要**自建 bigram 影子列**才能稳定召回 |
| 直接套 `sqlite-fts4` 的 BM25 SQL | **跑不了**。`rank(matchinfo(m,'pcnalx'))` → `Error: wrong number of arguments to function rank()`（可在目标机复现）；自定义函数必须改名 `rank_bm25` |
| 标准 Robertson IDF 就行 | **小语料下会失效**。`max(log((N-df+0.5)/(df+0.5)),0)` 在 df ≥ N/2 时归零；必须换 Lucene 变体 `log(1+(N-df+0.5)/(df+0.5))` |

**最致命的一条（直接改需求实现）**：plain BM25 **会稳定返回过期事实**。5 对「同谓词不同时间」的记忆（杭州 365 天前 vs 成都 3 天前、后端 400 天前 vs 前端 6 天前）BM25 分数**完全打平**，胜负由 rowid 决定 → 5/5 全部返回最旧那条。加时间衰减 `0.6 + 0.4*exp(-age_days/30)` 后 5/5 全部纠正。
→ 对虚拟伴侣这就是「你还住在杭州吧」这种翻车。**时间衰减必须做，半天工作量。**

**性价比最高的改动（1.5 人日）**：只改**写入侧**，把事实写成 mem0 `ADDITIVE_EXTRACTION_PROMPT` 风格（自包含 + 括号塞口语同义词 + 绝对时间），去重只做 md5，合并只做纯 ADD。实测把 top1 从 **73% → 91%**、top3 从 73% → 100%。排序侧所有调优加起来只值 +1.6 个百分点。
→ 顺带更正一个流传说法：mem0 v2.2.1 默认路径已是**纯 ADD**，四动作 UPDATE/DELETE 只剩显式 API。弱模型上四动作必错，纯 ADD 更稳，对我们有利。

**本地 embedding 明确不做**：体积上 ORT arm64 native 6.3MB + potion-base-2M 7.5MB = 13.5MB 起步，bge-small-zh int8 要 30MB；算力上目标机 FP32 256³ matmul 实测 **0.59 GFLOPS**、INT8 dot **0.25 GOPS**，24M 参数模型单句推理是数十秒级（RTF ≫ 1）。

**性能实测**（2000 轮对话建库）：建库 0.26s、db 909KB、单次 3-term OR + matchinfo 查询 **1.8ms**、进程峰值 **8.4MB**。远低于 150MB 预算。

**License 义务**：acp-kernel 是 MIT **+ 附加署名条款**，唯一义务是在 About 页写一行 `Uses billion-context / acp-kernel` + 两个 GitHub 链接。照做。

### 3.1 状态机与「不自唤醒」

- `Idle` 只跑 KWS（8.4MB，单核占用估 8–15%）；AudioRecord 常开 30–60mA 是主要耗电，所以加「息屏后可选停止 KWS」开关。
- **TTS 播放期间**：KWS 暂停、ASR 暂停，靠 AEC 兜底（防止自己的声音被 KWS 又命中一次）。
- TTS 播完 → 回 `Awake` 并**重置 8 秒计时器**（不是从唤醒那一刻算）。
- 唤醒即出「嗯？」短提示（可关），给用户反馈。

### 3.2 口型驱动（写死函数，用户已同意不做真同步）

不依赖字幕时间戳，直接对**正在播放的 PCM** 分帧算 RMS：

```kotlin
// AudioTrack 写入前
val rms = sqrt(frame.sumOf { (it.toInt() * it.toInt()).toDouble() } / frame.size)
val target = (rms / 3000.0).coerceIn(0.0, 1.0)
mouth = mouth * 0.6 + target * 0.4      // 平滑，防抖
```
每个 ~33ms 窗口推一次 `window.L2D.setMouth(v)` → `setParameterValueById('ParamMouthOpenY', v)`。
另外 ticker 里跑 `ParamBreath`（呼吸）、`ParamAngleX/Y/Z`（轻微摇头）、`ParamEyeLOpen/ROpen`（眨眼，随机 3–6 秒一次）。

**为什么不用字幕时间戳**：火山 bidirection 虽然也返回 `subtitles[]`，但要多解一层 JSON 且碎片化；能量法 30 行代码，视觉上已经够（用户明确说「口型不需要真的」）。

### 3.3 LLM 结构化输出

系统提示要求模型返回**单行 JSON**：

```json
{"say":"哼，主人终于想起我了？","emotion":"tsundere","motion":"head_tilt"}
```

- 解析失败（模型不听话）→ 整段当 `say`，`emotion` 默认 `neutral`。
- `emotion` → 映射到 exp3 表情（15 个待扫描注册，或用 `ParamMouthForm` / `ParamBrowLY` 组合近似）。
- 协议层面用 `response_format` 有兼容风险（很多第三方端点不支持），所以**只靠 prompt 约束 + 容错解析**，不硬依赖。

| ② 自定义角色卡 | 改 Character 的 `persona` 为「傲娇」并保存，再问「你是谁」 | 人设立刻生效；Persona 里的「主人称呼」体现在回复里 |
| ③ Live2D + 互动 | 启动即见角色；点击角色（或按钮）触发写死动作（点头/眨眼/换表情）；可导入自己的 `.model3.json` | 角色满屏渲染 fps≈22，点击有反应，导入后重启即换模型 |
| ④ 语音唤醒关联角色名 | 对着麦克风说「小鲸」 | 3 秒内进入 Awake，字幕出「在呢」或提示音，界面有状态指示 |
| ⑤ 唤醒后语音交流 | 说「今天好累」，等回复；不说话 8 秒 | 云端 ASR 出字 → LLM 回话 → TTS 出声 + 口型动 → 8 秒静默后自动回 Idle |

**交付物**
1. `app/build/outputs/apk/debug/app-debug.apk`（可 `adb install` 直接用）
2. 完整源码（本工作区，Gradle 可直接 `./gradlew :app:assembleDebug`）
3. `README.md` 一页（安装、配置、五条验收步骤、已知限制）

## 五、风险与对策

| # | 风险 | 证据 | 对策 | 残余风险 |
|---|---|---|---|---|
| R1 | 本地 ASR 在 A53 上太慢导致「说完半天不出字」 | 14M int8，RTF 估 0.5–0.7（推测） | **默认云端**，本地只在设置页手动开；云端失败自动降级；先实测 RTF 再决定默认值 | 中 |
| R2 | WebView 103 太老，某天 pixi/新库不兼容 | 已实测 pixi 6.5.10 + cubism4.min + Core 5.1.0 全通 | 所有 JS 都 vendor 进 assets，不联网拉库，版本锁死 | 低 |
| R3 | 8192 贴图超 `MAX_TEXTURE=4096` | 实测硬上限 | 已降到 2048（1.1MB/16MiB）；导入自己模型时若超限，自动降采样并提示 | 低 |
| R4 | 无 TTS 引擎 / 无 GMS | `tts_default_synth=null`，204 包无 tts | 全链路自带（火山 WS + AudioTrack），完全不用系统 TTS / SpeechRecognizer | 低 |
| R5 | 3GB 内存 + 256MB heap growth limit | dumpsys | 单角色实测 PSS 113MB；大图走 `.apk mmap` 不占 Java 堆；记忆库限 5000 条 | 低 |
| R6 | **大肥鱼模型授权不明** | `.vtube.json` 有 `"WorkshopSharingForbidden": true`，包内零许可文本 | 仅内部验证，**不进任何对外发布包**；App 默认不含模型，首次启动引导用户自己导入 | 高（法务） |
| R7 | 模型无 motion3，动作僵硬 | 包内 0 个 motion3、0 个 pose3 | cdi3 的 174 参数代码驱动 + physics3 被动摆动；「动作」用参数组合近似（点头/歪头/眨眼/口型） | 低（用户已接受） |
| R8 | 唤醒词被误触发（「小金」「小津」等） | 中文同音多 | keywords 里设 `#0.35` 阈值 + `:2.0` 提权；连续命中 2 帧才算；可调灵敏度滑块 | 中 |
| R9 | 火山的二进制帧头写错 → 连不上 | byte0/1/2/3 位域、大端 payload size | 已从官方文档核实字段表；先写一个「纯文本 ping」探针验证连接，再接音频 | 中 |
| R10 | 用户不提供密钥 → 验收走不通 | — | 双轨 demo：文字 + Live2D 全通；语音链路在「无密钥」时给出明确配置指引，不崩不卡 | 低 |
| R11 | Android 12+ 麦克风 FGS 限制 | 官方文档限制 | **本机是 Android 11，不受此限**；仍按新规设计（只在前台/用户显式启动时开） | 低 |
| R12 | 子代理并发吃 CPU 影响真机构建 | m00655 用户提醒 | 构建/安装阶段不派重型子代理；`assembleDebug` 已实测 48s（36 tasks） | 低 |
| R13 | **APK 实测 98.7MB**，远超预估 | 解包统计：`lib/*.so` 31.4MB + **dex 30.5MB** + `assets/asr` 25.7MB + `assets/kws` 6.5MB + `assets/l2d` 4.0MB | D4 已决定保留本地 ASR；dex 30.5MB 是 Compose BOM 2026.02.01 + debug 未压缩所致（`classes.dex` 9700 类 / `classes6.dex` 6516 类），release 开 R8 可显著下降；debug 包接受 99MB | 低（3GB/23GB 空闲，`adb install` 数秒） |
