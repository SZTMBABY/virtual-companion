## p1-3 新增 Live2D 渲染组件（WebView 承载）

**做了什么**：WebView 承载 `assets/l2d/render.html`，用 pixi.js 6.5.10 +
pixi-live2d-display 0.4.0（cubism4 构建）+ 官方 Cubism Core 5.1.0 渲染 moc3 v5 模型。
渲染层包在 `Live2DController` 后面（`setMouth`/`setSpeaking`/`setEmotion`/`setGaze`/`setView`/`reset`），
将来换 Native SDK 只替换这一个文件。

**改了哪些文件**：`ui/live2d/Live2DView.kt`、`ui/main/MainScreen.kt`、
`assets/l2d/render.html`、`MainActivity.kt`。

**怎么验证**（真机 `<device-serial>`，logcat tag `Live2DView`）：
```
Live2D Cubism Core version: 05.01.0000 (83951616)
L2D params {"ParamAngleX":27,...,"ParamEyeLOpen":14,"ParamMouthOpenY":18,"ParamBreath":37}
L2D layout canvas=400.8x534.2 half=false scale=0.10486 box=348.8x523.5
L2D_READY drawables=136
```
截图 `docs/proof/p1_main_port.png`（480×640，角色完整居中）。

**四个必须记住的渲染坑**（都已修进 `render.html`）：
1. `<script src>` 不能用 `l2d/pixi.min.js`——render.html 自己就在 `assets/l2d/` 下，写 `pixi.min.js`。
2. Cubism4ModelSettings **强制**要求 settings JSON 顶层有字符串 `url`，原模型包没有 → 必须注入。
3. `FileReferences` 里所有相对路径都要转成绝对（Moc / Textures / Physics / DisplayInfo /
   Expressions / Motions / Sound）。
4. `Groups.EyeBlink.Ids` 与 `Groups.LipSync.Ids` 在原包里是**空数组** → 必须补
   `['ParamEyeLOpen','ParamEyeROpen']` / `['ParamMouthOpenY']`，否则不眨眼不张嘴。

**黑屏真因**：`#stage{position:absolute;inset:0}` 在 Chromium 103 的 WebView 里把百分比高度
解析成 0，canvas 变成 h=0 的不可见元素（GL 照常渲染、readPixels 有像素，屏幕一片空白）。
修法：`position:fixed` + `applyCanvasSize()` 显式写 px，并给 `viewport()` 加兜底。

**抽搐/更快真因**：库里 `_render()` 已经用 `internalModel.update(deltaTime, elapsedTime)` 驱动，
第一个参数是**毫秒增量**、第二个是**毫秒累计**。我手写时传成 `update(nowMs, dtMs)`（反了），
累计时间被当成每帧增量喂给呼吸/摆动相位，于是越跑越快。
修法：不手动调 update，保持 `autoUpdate` 默认 true，把写参数挂在
`internalModel.on('beforeModelUpdate', ...)` 上（时序在 motion/expression/eyeblink 之后、
`coreModel.update()` 之前）。
验证：`L2D_JITTER2 updCalls=59 ticks=58 jumps={...全 0}`，每帧恰好一次 update。

**巨物真因**：`layout()` 不幂等——`getBounds()` 返回已乘 scale 的世界坐标，切前后台触发
resize 会再次放大 9.3 倍。修法：测量前 `model.scale.set(1); model.position.set(0,0)`。

**用户确认**：m01208「正常了」。

**新增需求（用户 m01154）**：半身模式。`DisplayConfig(halfBody=false, halfBodyRatio=0.48)`，
JS 侧 `view` + `layout()` 分支 + `__l2d.setView()` + URL 参数 `half=1&ratio=0.48`。
半身只按**高度**定缩放（允许左右溢出），因为该角色细长（3326×4992），
取 `min(CW/w, CH/(h*ratio))` 后宽度约束永远更紧，实测只放大 12%（0.10486 → 0.11810），
等于没效果；改成 `s = CH/(h*ratio)*0.98` 后实测 0.21847（2.08 倍），
渲染盒 726.6×1090.6，fps 28。截图 `docs/proof/p1_halfbody_port2.png`。

**有无偏离**：无。实现层调整：初版半身用 `min()` 导致无效，属实现 bug 而非口径变更。

## p1-4 限制渲染帧率为 24

**做了什么**：`render.html` 里设 `PIXI.Ticker.shared.maxFPS = 24`（可由 URL 参数 `fps` 覆盖，
默认 24）。用户 m01343 要求「限制帧率到24，避免卡顿」。

**为什么只改 Ticker 的 maxFPS**：`PIXI.Ticker.shared` 同时驱动 `_render()` 与库的
`onTickerUpdate → autoUpdate → internalModel.update`，所以一个开关能同时降渲染帧与模型动画帧，
不会出现「画面 24fps、动作 60fps」的错位。

**怎么验证**：logcat 出现 `L2D fps cap=24`；界面状态条 fps 从 28–29 降到 **22**（实测值略低于
24 是 WebView 与采样口径的正常差）。

**结果**：帧率稳定在 ~22fps。`dumpsys gfxinfo` 仍显示 91.69% janky，但那是 WebView
主线程统计口径（含合成与纹理上传），与用户可感知的动画平滑度不是一回事；
视觉最终判定权在用户（m01242）。

**有无偏离**：无。

## p2 接入 OpenAI 协议大模型（SSE 流式）

**做了什么**：
- `data/chat/ChatMessage.kt`：消息模型（role/content/seq）+ `SayExtractor`（流式半截 JSON 的 `say` 抽取）
- `data/chat/ChatClient.kt`：`POST {baseUrl}/v1/chat/completions` + `stream:true`，手写 SSE 行解析；
  `PromptBuilder` 组装两层角色卡 + 单行 JSON 输出协议
- `data/chat/ConversationStore.kt`：对话历史（SharedPreferences，上限 100 条）
- `AppContainer`：加 `conversation` / `chat` 两个 lazy
- `MainActivity`：`onSend` 走真实请求，流式增量更新字幕，`onDone` 落盘 + 切情绪
- `res/xml/network_security_config.xml` + Manifest `android:networkSecurityConfig`

**三个值得记的实现决策**：
1. **不用 OkHttp `EventSources`**：它绑死了 `data:` 解析与生命周期，而我们需要在
   `onFailure` 里区分「用户连发打断」与「网络断了」。自己读 `readUtf8Line()` 更简单。
2. **字幕边收边解**：模型输出 `{"say":"...","emotion":"..."}`，但流式到达时是半截 JSON。
   等完整再显示会让用户盯着空白；直接显示原文会出现 `{"say":"主` 这种噪音。
   `SayExtractor` 定位 `"say"` 之后一直读到未闭合的引号为止，把已到达的部分当字幕。
3. **历史用 SharedPreferences 不用 Room**：p5 的记忆层要整体重做存储
   （`Message` + FTS4 bigram 影子列 + `Block` 分层摘要），现在上 Room 等于白写迁移。
   这里的数据结构已按 p5 的 `Message` 对齐（role/content/seq），迁移时直接灌进去。

**踩坑 1：CLEARTEXT 被拦**
现象：字幕显示 `网络断了：CLEARTEXT communication to 127.0.0.1 not permitted by network security policy`。
根因：Android 9+ 默认禁明文 HTTP。用户的真实场景（Ollama :11434、one-api、局域网）全是 http，
必须放开。修法：加 `network_security_config.xml` 的 `base-config cleartextTrafficPermitted="true"`
并显式写 `trust-anchors`（比 `usesCleartextTraffic="true"` 更可控，将来按域名收紧只改一份 XML）。
设置页与 README 都提示「公网端点请用 https」。

**踩坑 2：mock 服务器一个 chunk 都发不出去**
`tools/mock_openai.mjs` 里把 `clearInterval` 挂在 `req.on('close')`，
但 Node 16+ 里 `IncomingMessage` 的 `close` 在**请求体读完时**就触发，定时器被立刻清掉。
改成 `res.on('close')` 后正常。

**怎么验证**（真机 + `adb reverse tcp:8080 tcp:8080` + `node tools/mock_openai.mjs`）：
- mock 侧日志：`model=deepseek-chat stream=true messages=3`、`last user: "hello"`
  （→ 证明请求体正确：1 条 system + 1 条 user）
- 界面截图 `.tmp_probe/s4.png`：字幕干净显示 `主人终于来啦，我一直在等你呢。今天想聊点什么？`
  （**没有** `{"say":` 噪音，说明 `SayExtractor` 生效）
- 历史落盘：`run-as ... cat shared_prefs/virtual_companion_chat.xml` →
  `[{"role":"user","content":"hello","seq":1},{"role":"assistant","content":"主人终于来啦…","seq":4}]`
- 情绪：`onDone` 里 `emotion = reply.emotion` + `controller.setEmotion(reply.emotion)`，
  渲染侧 `EMOTIONS` 表已覆盖 happy/sad/angry/shy（`render.html` 第 74–79 行）

**有无偏离**：无。新增一个 `tools/mock_openai.mjs` 测试工具（不入 APK），
属实现层新增，不影响验收口径。

## p3 语音唤醒：KWS + 本地 ASR + 唤醒后链路

**做了什么**
常开麦克风 → 本地 KWS 等「小鲸」→ 命中进入 AWAKE → 本地/云端 ASR 出字 →
交给 LLM → 播报时关麦 → 8 秒静默退回 IDLE。

**改了哪些文件**
- `voice/AudioCapture.kt`（新建）：16kHz 单声道，**1600 样本 = 100ms 一帧**，
  音频源三级回退 `VOICE_RECOGNITION → VOICE_COMMUNICATION → MIC`。
- `voice/KwsEngine.kt`（新建）：sherpa-onnx `KeywordSpotter`，关键词来自
  `assets/kws/keywords.txt`。所有公开方法 **`@Synchronized`**（见踩坑 2）。
- `voice/LocalAsrEngine.kt`（新建）：sherpa-onnx 流式 zipformer-zh-14M int8，离线兜底。
- `voice/VoiceEngine.kt`（新建）：状态机 `IDLE/AWAKE/THINKING/SPEAKING/ERROR`，
  播报时关麦、8 秒静默退出、本地/云端 ASR 自动降级、DEBUG wav 注入通道。
- `voice/AsrBackend.kt`（新建）：ASR 后端接口，p4 的腾讯云 WebSocket 直接实现它，
  换后端不动状态机。
- `voice/KwsSelfTest.kt`（新建）：离线自检，wav 帧喂给 KWS 并打命中/解码统计。
- `MainActivity.kt`：接麦克风权限（`RequestPermission`）、`sendText()` 统一文字与
  语音两条入口、`ON_STOP` 停麦（前台才开麦，后台常驻是 p6 的开关）。
- `data/SettingsStore.kt`：所有字段统一从根 JSON 读（见踩坑 4）。
- `app/src/main/assets/kws/keywords.txt`（新建）：`x iǎo j īng :2.0 @小鲸`。
- `data/model/AppSettings.kt`：`kwsThreshold` 默认 0.35 → **0.15**。

**踩坑 1：唤醒词阈值 0.35 太高 + 行内 `#阈值` 语法会让整行失效**
现象：真机上怎么说「小鲸」都不唤醒，但引擎日志显示在正常解码。
定位：造 6 个词表变体 × 3 个阈值，跑合成音频矩阵。结果：
- `x iǎo j īng @小鲸`：th=0.35 不中，**th=0.15 命中**，th=0.05 命中
- `x iǎo j īng #0.3 @小鲸`：**0.35/0.15/0.05 全不中**
→ 行内 `#<阈值>` 在本机（sherpa-onnx v2.0.1 + kws 模型 2025-12-20）会让整条关键词
失效；阈值只能从 `KeywordSpotterConfig.keywordsThreshold` 全局设，且必须 ≤0.15。
修法：词表只留 `x iǎo j īng :2.0 @小鲸`，阈值默认值改 0.15。
**追加坑**：改默认值后设备上仍旧不生效，因为 SharedPreferences 里存了旧的
`kwsThreshold:0.35`。必须 `rm shared_prefs/virtual_companion_settings.xml`。

**踩坑 2：`KeywordSpotter` 非线程安全 → SIGSEGV 直接闪退**
现象：注入测试时 App 崩溃。
logcat：`Fatal signal 11 (SIGSEGV) ... in libsherpa-onnx-jni.so`，
栈顶 `Java_com_k2fsa_sherpa_onnx_KeywordSpotter_decode+52` ← `KwsEngine.feed+78`
← `VoiceEngine.onFrame+484`。
根因：麦克风采集线程与注入线程并发调 `decode`。
修法：`KwsEngine` 的 `load/feed/reset/release` 全加 `@Synchronized`，
`VoiceEngine.onFrame` 用 `frameLock` 串行化（原主体拆成 `deliver()`）。
修后 `grep -c "Fatal signal"` = 0。

**踩坑 3：唤醒瞬间同步加载本地 ASR 要 8 秒，首句必丢**
现象：KWS 命中后 `→ AWAKE` 比 `HIT` 晚 **8.04 秒**，随后 `final: ''`。
根因：`enterAwake()` 里同步 `new LocalAsrEngine + load()`，24.5MB onnx 在 MT6761
上冷启动实测 **8127ms**，这 8 秒音频帧全被阻塞丢弃。
修法：`VoiceEngine` 持有唯一的 `localAsr`（`by lazy`），在 `start()` 的后台 IO 里
**预热**（日志 `local asr warmup 8127ms`），`LocalAsrBackend` 只借用不重建。
修后：`HIT` 到 `→ AWAKE` 间隔 **6ms**，首句正常出字。

**踩坑 4：API Key 明明填了却报「还没有填 API Key」**
现象：prefs 文件里 `app_settings.llm.apiKey` 有值，界面却提示没填。
根因：`SettingsStore` 早期把 `llm/tts/wake` 存成**并列的顶层 key**，
与根 JSON（`app_settings`）里的同名嵌套字段各存一份；两处不同步时读到了空的那份。
修法：所有字段统一从根 JSON 读（`private fun root() = AppSettings.fromJson(readJson(KEY_ROOT))`），
顶层 key 只写不读，兼容旧数据。

**踩坑 5：扬声器回放测唤醒根本测不通（物理限制，不是代码 bug）**
现象：`tinyplay` 播「小鲸」，麦克风峰值 0.02–0.13 但 KWS 的 `raw` 始终为空。
根因：`src=6` = `VOICE_RECOGNITION`，该源自带 AEC/NLP，**把自家扬声器的声音当回声消掉**。
结论：「扬声器 → 麦克风 → 唤醒」在本机物理上测不通，必须用 App 内注入验证管线。
→ 保留 `VoiceEngine.debugInjectWav()`（仅 DEBUG），注入前必须 `capture.stop()`，

## p4 云端语音：腾讯 ASR + 火山豆包 TTS 双向流式

**踩坑 1：火山事件号初版全错，三帧抢跑被服务端丢弃**
初版凭记忆写了 StartSession=50 / TaskRequest=51 / FinishSession=52 / TTSEnded=353，
全部错误。抓官方文档 `https://www.volcengine.com/docs/6561/1329505` 逐条核实后修正：

| 事件 | 正确值 | 初版（错） |
|---|---|---|
| FinishConnection | 2 | 53 |
| StartSession | 100 | 50 |
| FinishSession | 102 | 52 |
| SessionFinished | 152 | 151 |
| SessionFailed | 153 | 152 |
| TaskRequest | 200 | 51 |
| TTSEnded | **不存在** | 353 |

协议还有时序硬约束：必须先收到 `ConnectionStarted(50)` 才能发 `StartSession(100)`，
先收到 `SessionStarted(150)` 才能发 `TaskRequest(200)`。初版三帧一口气发，服务端直接不理。
修法：`speak()` 只发 StartSession 并存 `pendingText`，收到 150 后在 `flushTaskRequest()` 里补发 200 + 102。

**踩坑 2：连接级事件的 body 里没有 session_id 段**
现象：`decode ws request failed: unable to decode V1 protocol message:
declared body size does not match actual body size: expected=0 actual=6`。
根因：连接级事件（1/2/50/51/52）的 body 直接是 `uint32 payloadLen + payload`，
没有 `uint32 sidLen + sid`；初版给所有帧都写了 0 长度 sid，服务端把它当成了 payload 长度。
修法：`buildFrame()` 里 `if (event !in CONNECTION_EVENTS) { 写 sidLen + sid }`。
`parseFrame()` 相应改成启发式：长度合理（0..256）且后面还放得下 payload size 才当 id 读，
因为服务端回 ConnectionStarted 时**会**带 36 字节的 connect id。

**踩坑 3：TTS 播完状态卡在「说话中」不动**
现象：截图显示 chip 一直「说话中」，日志有 `SessionFinished` 但没有回到 AWAKE。
根因两处叠加：
1. `TtsPlayer` 播放线程 `queue.poll(60ms) ?: continue` —— 队列排空后永远返回 null，
   死循环，`finally { onIdle?.invoke() }` 永不执行。
2. `VolcanoTtsClient` 收到 `SessionFinished(152)` 只 `countDown()`，**没有通知播放器「没有音频了」**。
修法：`TtsPlayer` 加 `@Volatile inputDone` + `markInputDone()`，播放循环改成
「队列空且 inputDone → break，否则继续等」；`VolcanoTtsClient` 在 152 分支补 `onDone?.invoke()`；
`VolcanoTtsSpeaker` 的 `onDone` 里调 `p.markInputDone()`。
